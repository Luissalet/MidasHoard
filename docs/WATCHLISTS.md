# Listas de seguimiento

En Mercado selecciona las instantáneas habituales, escribe un nombre y pulsa «Guardar selección como nueva lista». El selector recupera la lista después de recargar. «Renombrar» cambia sólo el nombre; «Añadir selección» conserva las demás entradas, y «Quitar de la lista» elimina sólo esa pertenencia, sin borrar datos. Cada combinación proveedor/símbolo aparece una vez; añadir una versión nueva reemplaza su referencia.

La tabla muestra último valor, variación, caída, fechas, observaciones, moneda/unidad, frecuencia y procedencia. El periodo abarca hasta el número de intervalos elegido: veinte intervalos necesitan veintiuna observaciones. No se rellenan fechas ausentes. El corte por fecha excluye datos posteriores dentro de las instantáneas guardadas; no recupera vintages históricos del proveedor. El porcentaje de variación queda vacío si no hay dos observaciones o la base no es positiva. La caída se calcula sobre el máximo previo del periodo si todos los valores son positivos. No hay suma de monedas ni conversión implícita.

Los filtros por símbolo/proveedor, moneda, variación mínima y magnitud máxima de caída se aplican antes de ordenar/paginar. Los resultados sin la métrica quedan al final; los errores de integridad o entradas sin datos se mantienen visibles al consultar sin filtros numéricos. La procedencia incluye el SHA de la instantánea. Los cursores respetan también el presupuesto compartido de resultados MCP para no saltarse filas grandes.

«Actualizar datos» utiliza los proveedores ya presentes. Crea nuevas instantáneas sin alterar las anteriores; conserva frecuencia, moneda y comienzo solicitado. Las importaciones CSV permanecen fijadas: importar otra versión y añadirla permite sustituir su referencia. Un fallo de un proveedor conserva el último dato útil y aparece en el resultado parcial. La publicación actualiza sólo entradas cuyo proveedor/símbolo y referencia capturada siguen vigentes; renombres, añadidos, eliminaciones y sustituciones simultáneas se conservan. `attached=false` indica una descarga correcta cuyo resultado no sustituyó una edición posterior.

Cuatro herramientas comparten el flujo nativo: `watchlists_list`, `watchlist_save`, `watchlist_view`, `watchlist_refresh`, dentro de27 herramientas. La API equivalente vive bajo /api/watchlists. `watchlist_save` acepta actualizaciones parciales; omitir un campo lo conserva. `entries` reemplaza el conjunto explícitamente; `add_entries` y `remove_entries` hacen cambios de pertenencia sobre la lista vigente. Las entradas admiten snapshot_id o proveedor/símbolo; este último puede representar una serie todavía no descargada. Las consultas no usan red ni LLM; actualizar utiliza los servicios de datos existentes.

La UI y el MCP usan código propio. No ejecutan ni importan la aplicación de referencia. No se añaden proveedores, modelos o operaciones de contratación. Las pruebas usan datos sintéticos y CSV inventados; la disponibilidad y cobertura de proveedores reales conserva sus condiciones actuales.

Los valores originales finitos pueden producir una métrica fuera del rango numérico. Esa métrica devuelve null con una explicación por fila; el último dato, su procedencia y las demás series siguen disponibles. No se publica Infinity ni NaN como un resultado válido ni se rechaza toda la lista por ese caso.
